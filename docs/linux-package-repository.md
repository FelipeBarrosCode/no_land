# Linux package distribution

Noland Connect publishes Debian packages for Ubuntu and Debian on the GitHub
release page. The package is a normal `.deb`; it is not automatically listed in
Ubuntu App Center, whose primary third-party distribution format is Snap.

## Verify a downloaded package

Download the `.deb` and the matching `SHA256SUMS` file from the same release:

```sh
sha256sum --check SHA256SUMS --ignore-missing
sudo apt install ./noland-connect_<version>_<architecture>.deb
```

The release workflow also validates the package with `dpkg-deb` and `lintian`.
The package contains AppStream metadata at
`/usr/share/metainfo/com.noland.connect.metainfo.xml` so compatible desktop
software centers can discover it when the package is installed.

## APT repository requirements

A future APT repository must publish, for every supported suite and component:

- `dists/<suite>/<component>/binary-<architecture>/Packages` and compressed indexes
- a `Release` file containing checksums for every index
- an OpenPGP detached or inline signature for `Release`
- the `.deb` files under `pool/`

Repository metadata must be generated by a tool such as `reprepro`, `aptly`, or
`apt-ftparchive`, and signed in CI with a dedicated signing key stored in the
repository host's secret store. Private keys must never be committed to this
repository or embedded in the application.

Users should install the repository key into a dedicated keyring and use
`signed-by`; do not use the deprecated global `apt-key` mechanism. A production
repository should publish its key fingerprint and rotate keys with a documented
overlap period before adding a replacement key.

The current release workflow publishes checksummed release artifacts. Tauri
updater artifacts have their own updater signatures, but those signatures do
not sign the `.deb` files or APT metadata. The workflow does not claim to
provide an APT repository until a hosting location and a protected signing-key
secret are configured.

## Trust and privileged components

Noland Connect includes native helper/sidecar binaries and can use privileged
Linux networking operations through the system authorization mechanism. Review
the source and package contents before installation. The package must not use a
`postinst` script to download or execute code from the network; updates are
obtained from the signed release process instead.
